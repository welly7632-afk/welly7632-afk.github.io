## 1. 一句話＆可以拿來做什麼（針對這位使用者）

**一句話：** Ruler 是一個 Node.js 命令列工具（`npm` 套件 `@intellectronica/ruler`，指令 `ruler`），你只維護 `.ruler/` 這一個資料夾裡的 Markdown 規則、`ruler.toml` 設定、`skills/` 技能和 `agents/` 子代理；執行 `ruler apply`，它就把同一份內容「翻譯＋複製」到 Claude Code 讀的 `CLAUDE.md`、`.claude/skills/`、`.claude/agents/`、`.mcp.json`，以及 Codex 讀的 `AGENTS.md`、`.agents/skills/`、`.codex/agents/*.toml`、`.codex/config.toml`，另外還支援 Cursor、Copilot、Gemini CLI、Firebase Studio 等，共 32 個轉接器。

**對你（GPT／Codex＋Claude 一起寫倉儲系統、覺得很亂）最直接的價值：**

1. **解決「CLAUDE.md 跟 AGENTS.md 各寫各的」→ 新舊版本衝突的根源。** 你以後只改 `.ruler/` 裡的檔案，兩份輸出檔永遠是同一份內容的產物；每段內容前面還會自動加 `<!-- Source: .ruler/xxx.md -->` 標記，AI 或你自己都能追到「這條規則從哪個檔案來」。
2. **技能（Skills）與子代理（角色）也只寫一次。** `.ruler/skills/<名稱>/SKILL.md` 會被同步到 `.claude/skills/`（Claude）和 `.agents/skills/`（Codex）；`.ruler/agents/<角色>.md`（例如 reviewer、patroller）會被轉成 Claude 的 Markdown 子代理和 Codex 的 TOML 子代理，連「唯讀」設定都會翻譯（Codex 變成 `sandbox_mode = "read-only"`）。
3. **現成的「防漂移」CI 範例和「定期 AI 巡檢」範例。** README 提供一段 GitHub Actions：每次 PR／push 都重跑 `ruler apply`，若產生的 AGENTS.md／CLAUDE.md 跟 commit 進去的不一樣就讓 CI 失敗；repo 自己還有一個「每週三自動派 Copilot 代理去比對 README 跟程式碼是否一致，只做最小修正並開 PR」的排程 workflow，提示詞寫得很好，可改成你的每日巡讀。
4. **你用 Firebase：** 它內建 Firebase Studio 轉接器，會把規則寫到 `.idx/airules.md`、MCP 寫到 `.idx/mcp.json`。

**它不做什麼（先講清楚）：** Ruler 是「規則分發器」，不是「巡讀員」。它**不會**檢查規則內容是否互相矛盾、不會合併重複的段落、不會追蹤任務（沒有 backlog／checklist）、也沒有角色範本（只提供寫角色的格式）。它也沒有「每天自動跑」的排程，要你自己用 GitHub Actions cron 或 hook 觸發。所以它適合當你「基礎架構的地基（單一事實來源＋自動同步）」，巡讀邏輯要另外寫成一個 skill／子代理，再交給 Ruler 同步。

## 3. 技術棧與執行需求

| 項目 | 內容 |
|---|---|
| 語言 | TypeScript（編譯成 `dist/`，CLI 入口 `dist/cli/index.js`） |
| 執行環境 | Node.js `^20.19.0 \|\| ^22.12.0 \|\| >=23`（[package.json `engines`](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/package.json)） |
| 執行期依賴（只有 4 個） | `@iarna/toml`（讀寫 TOML）、`js-yaml`（讀 YAML frontmatter）、`yargs`（CLI 參數）、`zod`（驗證 `ruler.toml` 格式） |
| 前端／後端／資料庫 | 都沒有。純本機 CLI，只讀寫專案資料夾裡的檔案 |
| 部署 | 不用部署。`npm install -g @intellectronica/ruler` 或 `npx @intellectronica/ruler apply` |
| 硬體／GPU | 不需要，任何能跑 Node 的電腦都行 |
| API Key | Ruler 本身不需要。只有你在 `ruler.toml` 裡定義的 MCP 伺服器可能要它們自己的金鑰（Ruler 只是把設定複製過去） |
| 費用 | 工具本身 0 元 |

**怎麼跑（README 給的流程）：**
```bash
npm install -g @intellectronica/ruler
cd 你的專案
ruler init                      # 建 .ruler/AGENTS.md 和 .ruler/ruler.toml
ruler apply --agents claude,codex   # 只產生 Claude 和 Codex 的檔案
ruler apply --dry-run           # 先預覽會寫哪些檔
ruler revert                    # 全部還原（用 .bak 備份）
```
另外有 `ruler init --global`，會在 `~/.config/ruler`（`$XDG_CONFIG_HOME/ruler`）建立全域規則。

## 7. AI／Claude 整合

- **用哪些模型：** Ruler 本身**不呼叫任何 AI 模型**，也不含 prompt 呼叫邏輯（搜尋 `src/` 中的 `fetch(`、`http://`／`https://`，只出現在註解和 OpenCode 的 `$schema` 字串，沒有網路請求程式碼）。它只是產生檔案。
- **Claude 支援：原生。** `ClaudeAgent` 產生 `CLAUDE.md`、`.mcp.json`、`.claude/skills/`、`.claude/agents/`；Codex 產生 `AGENTS.md`、`.codex/config.toml`、`.agents/skills/`、`.codex/agents/*.toml`（[README 支援表 #L55-L90](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L55-L90)）。
- **prompt 放在哪：** 你的規則就是 prompt，放在 `.ruler/*.md`；repo 自己唯一的「AI 任務 prompt」是 [writeme/prompt.md](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.github/workflows/writeme/prompt.md)（給 Copilot 代理用）。
- **MCP：** 在 `ruler.toml` 用 `[mcp_servers.名稱]` 定義一次，分發到各工具；也可用 `[agents.claude.mcp_servers.x]` 只給 Claude（[README #L519-L531](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L519-L531)）。
- **Skills：** 預設開啟（實驗性），只複製、不改寫內容（[README #L597-L766](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L597-L766)）。
- **Subagents（角色）：** 預設關閉，要 `--subagents` 或 `[agents] enabled = true`（[README #L768-L993](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L768-L993)）。
- **能不能換成 Claude：** 不需要換，Claude Code 本來就是一級支援對象；要「用 Claude 取代 Copilot 做每週巡檢」則需你自己改 workflow（Ruler 沒提供 Claude 版的巡檢 workflow，**未確認**任何官方範例）。

## 8. 擴充方式與 API

1. **加一個新的 AI 工具：** 在 `src/agents/` 新增一個類別繼承 `AbstractAgent`（只要實作 `getIdentifier`、`getName`、`getDefaultOutputPath`，最短像 [ClaudeAgent.ts](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/agents/ClaudeAgent.ts) 35 行），再加進 [`allAgents` 陣列 index.ts#L38-L71](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/agents/index.ts#L38-L71)。這需要 fork 並自己建置；**沒有外掛機制**。
2. **不改程式碼的擴充：** 用 `ruler.toml` 的 `[agents.X] output_path = "..."` 改輸出位置。例如有工具讀 `CLAUDE.md` 以外的檔，可指定路徑。
3. **程式化 API：** `package.json` 的 `main` 指向 `dist/lib.js`，[`lib.ts`](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/lib.ts) 匯出 `allAgents` 和 `applyAllAgentConfigs(...)`（#L131），參數是一長串位置參數（專案根、代理清單、設定檔、MCP、gitignore、verbose、dry-run、local-only、nested、backup、skills…），可以在你自己的 Node 腳本裡呼叫。
4. **CLI 旗標：** `apply` 有 `--agents`、`--config`、`--no-mcp`、`--mcp-overwrite`、`--no-gitignore`、`--gitignore-local`、`--nested`、`--no-backup`、`--no-skills`、`--subagents`、`--dry-run`、`--local-only`、`--verbose`（[README #L231-L252](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L231-L252)）。

## 9. 程式品質與風險

- **維護狀況：** 最近 push 2026-10-28；`package.json` 版本 `0.3.46`（還在 0.x，介面可能改）。README 頂端自稱「Beta Research Preview」。有 dependabot 每週更新 GitHub Actions。淺複製只有 1 個 commit，**提交頻率與貢獻者數未確認**。
- **測試：** 163 個測試檔；CI 在 Node 20.19 / 22.12 / 24 三版本跑 format、lint、test、build、`npm audit --omit=dev`、`npm pack --dry-run`（[ci.yml](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.github/workflows/ci.yml)）。我沒有執行測試，**通過率未確認**。測試檔名能看出曾發生過的坑：`duplication-fix`（重複 apply 內容倍增）、`corrupted-marker-fix`（標記壞掉導致讀回產物）、`mixed-agents-duplication`。
- **資安：** 寫檔前大量檢查（拒絕符號連結、硬連結、專案外路徑；MCP 設定不寫到家目錄），相當謹慎。
- **隱私／遙測：** 沒看到遙測或網路呼叫（搜尋方式見第 7 節）。
- **已知的坑（使用前一定要知道）：**
  1. **產生的 CLAUDE.md／AGENTS.md 會被覆蓋。** AI 或你直接改 `CLAUDE.md`，下次 `ruler apply` 就不見了（第一次會備份 `.bak`）。必須在規則裡寫明「規則只能改 `.ruler/`」。
  2. **預設會把產物加進 `.gitignore`。** 對多人／多台電腦／git worktree 不友善：新 clone 沒有 CLAUDE.md。README 建議改成 `[gitignore] enabled = false` 並把產物 commit 進去，再用 CI 檢查漂移（[README #L1052-L1124](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L1052-L1124)）。
  3. **預設對「全部 32 個工具」產檔。** 不設 `default_agents` 會冒出一堆 `.cursor/`、`.windsurf/`、`.kiro/` 等資料夾。務必設 `default_agents = ["claude", "codex"]`。
  4. **所有工具拿到的規則完全一樣。** 不能「只給 Claude 看某段」（[README FAQ #L1257-L1258](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L1257-L1258)），只能在內文寫「## Claude 專用」小節。
  5. **全域規則不會疊加專案規則。** 有專案 `.ruler/` 時，`~/.config/ruler` 完全不用（見第 5 節 `findRulerDir`）。
  6. **技能重名／不一致的檢查只在選了 OpenCode 才跑**；只用 Claude＋Codex 時不會有這個警告。
  7. **巢狀模式、skills、subagents 都標「實驗性」**；subagents 沒有 `revert` 支援。
  8. `UnifiedConfigLoader.ts` 會算每個規則檔的 sha256（#L258、#L283），但用 grep 查 `contentHash`／`concatenatedHash`，只出現在型別定義，**沒有被用來做漂移比對**。

## 10. 跟其他專案組合的建議

Ruler 的定位是「地基＝單一事實來源＋自動分發」。它本身缺「內容」和「巡檢」，建議這樣組：

- **Ruler（分發）＋ github/spec-kit（憲法格式＋analyze 稽核 prompt）：** 把 spec-kit 的「專案憲法」（有版本號、MUST/SHOULD、Sync Impact Report）寫成 `.ruler/00-constitution.md`；把 analyze 的六類問題（重複、模糊、規格不足、違反憲法、覆蓋缺口、不一致）改寫成 `.ruler/skills/daily-patrol/SKILL.md`。由 Ruler 同步給 Claude 與 Codex。
- **Ruler ＋ anthropics/skills（官方 SKILL.md 寫法）：** Ruler 只複製 skill，不教你怎麼寫；SKILL.md 的 frontmatter 與 description 寫法參考官方範例，再放進 `.ruler/skills/`。
- **Ruler ＋ VoltAgent/awesome-claude-code-subagents 或 BMAD-METHOD（角色內容）：** 挑 reviewer、QA、architect 等角色檔，改成 Ruler 的 `.ruler/agents/*.md` 格式（`name` 要等於檔名），一次產生 Claude 版與 Codex 版。
- **Ruler ＋ OpenSpec（變更提案／封存）：** Ruler 沒有「變更提案→封存」流程，OpenSpec 補這一塊，用來防新舊版本衝突。
- **跟你的倉儲 web app：** 在 repo 根放 `.ruler/`，`default_agents = ["claude", "codex", "firebase"]`（如果你用 Firebase Studio），規則檔寫「純 JavaScript、Firebase、不得引入框架」等專案慣例。

**建議給你的基礎架構（可直接照抄目錄）：**
```
.ruler/
├── AGENTS.md              ← 總綱：專案是什麼、單一事實來源聲明「規則只能改 .ruler/」、目錄說明
├── 10-architecture.md     ← 倉儲系統架構、Firebase 資料結構
├── 20-coding-style.md     ← 純 JS 慣例、命名
├── 30-roles.md            ← 誰（Claude/Codex）負責什麼、交接格式
├── 40-handoff-and-done.md ← 完成前檢查清單、交接紀錄寫在 docs/handoff/YYYY-MM-DD.md
├── ruler.toml             ← default_agents = ["claude","codex"]；[gitignore] enabled=false；[agents] enabled=true
├── skills/
│   └── daily-patrol/SKILL.md   ← 每日巡讀（見第 11 節範例）
└── agents/
    ├── reviewer.md        ← 唯讀審查員（readonly: true）
    └── patroller.md       ← 唯讀巡讀員
```

## 11. 規則／角色／巡檢 檢查表

### 共用規則怎麼寫 — **有**
- **檔案結構：** `.ruler/AGENTS.md`（主檔）＋任意 `.ruler/**/*.md`＋`.ruler/ruler.toml`。輸出成 `CLAUDE.md`（Claude）與 `AGENTS.md`（Codex 及多數工具）。見 [README #L131-L145](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L131-L145)。
- **分層：** 全域 `~/.config/ruler`（只在找不到專案 `.ruler/` 時用）→ 專案 `.ruler/` → 子資料夾 `src/.ruler/`（`--nested`，各自產生自己資料夾的規則檔）。見 [README #L147-L186](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L147-L186)。
- **優先順序：** 專案根手寫 `AGENTS.md`（若非產物）＞ `.ruler/AGENTS.md` ＞ 舊 `instructions.md` ＞ 其他 `.md` 依路徑排序（[FileSystemUtils.ts#L400-L484](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/FileSystemUtils.ts#L400-L484)）。設定的優先：CLI 旗標 ＞ `ruler.toml` ＞ 內建預設（[README #L482-L486](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L482-L486)）。
- **讓 GPT（Codex）和 Claude 讀同一份：** 這正是 Ruler 的核心；`ruler apply --agents claude,codex` 產生兩份內容相同（都由同一個 `concatenateRules` 輸出）的 `CLAUDE.md` 與 `AGENTS.md`。差別：`AGENTS.md` 第一行多了 `<!-- Generated by Ruler -->`；`CLAUDE.md` 沒有這個標記（用 grep 查 `writeGeneratedProvenance(` 的呼叫處，只有 `.bak` 備份、MCP 設定、Aider／Qwen／Firebender 設定會加旁檔標記），所以 CLAUDE.md 只能靠內文的 `<!-- Source: … -->` 看出是產物——建議在 `.ruler/AGENTS.md` 開頭自己寫一行「本檔由 Ruler 產生，請勿手改」。
- **範例：** 這個 repo 自己的 [`.ruler/AGENTS.md`](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.ruler/AGENTS.md) 只有 27 行：TDD、Prettier、在 feature branch 開 PR、PR 前必跑 `npm ci / lint / test / build`、AI commit 要用 `--author="AI <…>"` 方便辨識是 AI 改的。最後一條很值得借用：**讓每個 AI 用不同的 commit author**，巡讀時一眼看出哪個 AI 改了什麼。

### 角色設計 — **部分有（只有格式，沒有角色內容）**
- Ruler 提供「子代理」格式：`.ruler/agents/<name>.md`，frontmatter 必填 `name`（須等於檔名）、`description`（何時該委派給它）；選填 `tools`、`model`、`readonly`、`is_background`（[README #L788-L825](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L788-L825)）。README 唯一範例是 `code-reviewer`（唯讀審查員）。
- **工具權限：** `tools: [Read, Grep, Glob, Bash]` 給 Claude 原樣、Copilot 對照、OpenCode 轉權限；`readonly: true` 給 Codex 變 `sandbox_mode = "read-only"`（[SubagentsProcessor.ts#L435-L476](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/SubagentsProcessor.ts#L435-L476)）。
- **交接（handoff）、誰向誰負責：沒有。** 沒有任何交接格式或角色階層，要自己寫在 `.ruler/30-roles.md`。

### 防漏 — **沒有（只有開發流程規範）**
- 沒有 backlog／issue／checklist 機制。唯一相關的是 repo 自己的規則「宣告 PR ready 前必須所有 CI 通過」（[.ruler/AGENTS.md#L21-L25](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.ruler/AGENTS.md#L21-L25)）——這是一個「完成前驗證」的寫法範本。交接紀錄：沒有。

### 防重複 — **有（限於「產出檔」與「技能名」層級，不檢查規則內容）**
- 產物不會被讀回來造成內容倍增（[FileSystemUtils.ts#L462-L476](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/FileSystemUtils.ts#L462-L476)）；多個工具共用 AGENTS.md 只寫一次（[apply-engine.ts#L540-L549](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/apply-engine.ts#L540-L549)）。

- **規則內容重複／互相矛盾：沒有偵測。** 這一塊要靠你的巡讀 skill。

### 防新舊版本衝突 — **有（單一事實來源＋CI 漂移檢查），沒有版本號與封存**
- **單一事實來源：** `.ruler/` 是唯一來源；產物帶 `Generated by Ruler` 標記與 `<!-- Source: -->` 來源標記。
- **漂移偵測：** README 的 CI 範例「重跑 apply → `git status --porcelain` 有差異就失敗」（[README #L1077-L1124](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L1077-L1124)），以及 repo 自用的「push 後自動重產並 commit」（[ruler.yml](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.github/workflows/ruler.yml)）。
- **舊格式相容：** `instructions.md`、`mcp.json`、`[subagents]` 都還能讀但標為 legacy／deprecated（[ConfigLoader.ts#L115-L127](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/ConfigLoader.ts#L115-L127)）。
- **版本標記、變更提案、封存：沒有。** 規則檔本身沒有版本號欄位；建議借 spec-kit 的憲法版本號格式。

### 定期巡檢 — **有一個「每週文件巡檢」範例，沒有每日巡讀整個專案**
- [writeme.yml](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.github/workflows/writeme.yml)：`cron: '0 17 * * 3'`（每週三 17:00 UTC＝台灣週四凌晨 1:00），把 prompt 送給 GitHub Copilot 代理 API 開一個 PR，標題「README Accuracy Review & Minimal Update」。
- [writeme/prompt.md](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/.github/workflows/writeme/prompt.md) 的結構很適合改成你的巡讀：①硬性限制（只准改指定檔、不准猜、不准加新功能）②要驗證的清單（安裝、指令、設定、支援工具清單、檔案結構…對照 `src/`、`tests/`）③改動判準（宣稱不存在的、遺漏必要的、名稱過期的）④固定步驟（建事實地圖 → 逐段標記 accurate／outdated／missing detail／formatting issue → 最小修正）⑤「不確定就不改」。
- **報告格式：** 原版是 PR 描述「列出每個改動及原因」。改成你的每日巡讀，可要求輸出類似：

```markdown
# 巡讀報告 2026-11-05（patroller，唯讀）
| # | 類型 | 位置 | 說明 | 建議 | 嚴重度 |
|---|---|---|---|---|---|
| 1 | 新舊衝突 | CLAUDE.md 第 40 行 vs .ruler/20-coding-style.md | CLAUDE.md 被手改，與來源不同 | 改回 .ruler/ 後重跑 ruler apply | 高 |
| 2 | 重複 | .ruler/10-architecture.md、docs/inventory.md | 庫存欄位定義寫了兩次且欄位名不同（qty / quantity） | 保留 10-architecture.md，另一處改連結 | 中 |
| 3 | 遺漏 | docs/handoff/2026-11-04.md | Codex 說「待補單元測試」但沒有對應任務 | 新增到 TODO.md | 中 |
結論：accurate 12 段、outdated 2 段、missing 1 段；本次未修改任何檔案。
```
（上面是依 prompt.md 結構改寫的建議格式，不是 repo 內原文。）
- **hook：** Ruler 沒有 Claude Code hook；README 建議在 `package.json` 用 `"precommit": "npm run ruler:apply"`（[README #L1170-L1180](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L1170-L1180)），以及 worktree 情境下「請 AI 每次 session 開始先跑 `ruler apply`」。

### Skill 寫法 — **有（結構與驗證），description 寫法只有基本限制**
- 結構：`.ruler/skills/<skill-name>/SKILL.md`（必填）＋同資料夾的 `helper.py`、`reference.md` 等（腳本與參考文件放同一個技能資料夾內），可用分組資料夾多層巢狀（[README #L627-L649](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/README.md#L627-L649)）。
- frontmatter 規則（OpenCode 檢查，但也適用 Claude／Codex 慣例）：`name` 1–64 字、小寫英數與連字號、等於資料夾名；`description` 非空、≤1024 字（[OpenCodeSkills.ts#L96-L121](https://github.com/intellectronica/ruler/blob/5e551e60952fb1c81c6c5ad6f5fe8b7a412bda87/src/core/OpenCodeSkills.ts#L96-L121)）。
- 「description 怎麼寫才會被正確觸發」：Ruler **沒有**這方面指導；README 的 skill 範例甚至沒有 frontmatter。子代理 description 範例倒是示範了好寫法：「Use PROACTIVELY after a feature/fix is implemented. Reviews against SOLID/DRY/KISS. Read-only.」——先寫**何時用**、再寫**做什麼**、最後寫**限制**。
- 分發位置：Claude → `.claude/skills/`；Codex → `.agents/skills/`（與 Goose、Amp、Zed 共用）。
